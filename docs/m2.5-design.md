# M2.5 — The 10-foot design pass

Status: implemented; `crates/core` and `crates/app` build, lint and test clean in
`archlinux:latest` (214 app tests, 105 core), and two Xvfb runs render both
shells at 1080p and 4K with the console floor measured on screen. **Not
validated on a TV** — neither machine has one attached (ADR-0004). The console
grid, its filters and a console game page are the remaining M2.5 work.

This slice turns "the console shell is 10-foot" from a claim scattered across
twenty files of hard-coded `10px`–`16px` literals into a tested number. The
decision record is ADR-0028; this doc is the implementation.

## Why

Before this slice the console shell scaled only its base font and header. A card
title was 14 px, a caption 10–11 px and the muted grey `#78788a` sat on both
backgrounds at roughly 3.5:1 — unreadable from a couch and failing WCAG AA. A
10-foot shell is a claim about three things, and each was unchecked:

| Claim | Before | Now |
|---|---|---|
| Type floor | literals from 10 px | `18 px` console / `11 px` desktop, clamped after `ui_scale` |
| Contrast | `#78788a` ≈ 3.5:1 | every shipped pair ≥ 4.5:1, asserted |
| Hit areas | button default | `48 px` console / `28 px` desktop, asserted |

## What ships

### `pitagames_core::design` (framework-free)

`DesignTokens::for_shell(shell, &DisplayConfig)` resolves the five type roles and
the interaction numbers. Every size is `base × ui_scale`, then **clamped to the
shell's floor** — scaling the console shell down cannot make a caption unreadable.

```text
role      desktop  console     used for
title      28 px    40 px      hero + game titles
heading    16 px    26 px      panel/section headings
body       14 px    20 px      normal copy, buttons, rows
caption    12 px    18 px      secondary copy, nav, metadata
micro      11 px    18 px      uppercase labels, badges
hit-min    28 px    48 px      minimum control square
ring        2 px     2 px      focus ring width
```

`css_vars()` renders the roles as custom properties (`--text-title:40px;…`), and
the palette is a set of `Rgb` constants with the contrast math beside them:

- `Rgb::luminance()` is WCAG 2.1 relative luminance, `contrast_ratio()` the
  symmetric 1:1–21:1 ratio.
- The palette is `BACKGROUND`, `CONSOLE_BACKGROUND`, `CARD`, `TEXT`,
  `TEXT_SECONDARY`, `TEXT_MUTED`, `TEXT_DISABLED`, `ACCENT`, `WARNING`, `DANGER`,
  `SUCCESS`. `TEXT_MUTED` moved from `#78788a` (≈3.5:1) to **`#9a9aac`** (≈6:1)
  because the old value failed AA on both backgrounds.

### The shell seam (`crates/app/src/shell.rs`)

`root_style` emits the tokens and the palette on the app root. Both branches name
the same properties, because Dioxus's style setter keeps an inline property a new
style string omits.

```text
--text-title --text-heading --text-body --text-caption --text-micro
--hit-min --ring
--bg --card --text --text-secondary --text-muted --text-disabled
--accent --warning --danger --success
```

`header_style` now reads `--text-caption` and wraps, so the console header's
subtitle does not run off the edge. `HIT_FLOOR` is the one inline declaration of
the hit minimum, and `nav_style`/`button_style` are its named users.

### The CSS sweep (console-critical screens)

Every sized literal in these files became a role:

| File | What moved |
|---|---|
| `main.rs` | header, nav, play strip, notice, hand-off badge, grid cards, footer hints |
| `home_view.rs` | hero (title/meta/labels/buttons), shelf tiles, section labels |
| `detail.rs` | page title, panel headings, rows, buttons |
| `stores_view.rs` | store rows, session badges, sign-in terminal |
| `overlay_view.rs` | overlay rows (also gets `min-height:var(--hit-min)`) |
| `osk.rs` | sheet header, text caret, keys, Cancel/Done |
| `copy.rs`, `diagnostics.rs` | copy buttons and diagnostics chips |

`cursor:pointer` controls also receive `--hit-min`, so a pad or a fat pointer has
a 48 px target in the console shell and a 28 px one on the desktop.

### Two enforced invariants

A global stylesheet would be the natural home for the floor and the no-motion
rule, but **this Dioxus build does not apply a `<style>` element written in RSX**
(see *The probe* below), and injecting CSS would need JavaScript, which the
renderer boundary forbids. So both rules are enforced by tests over the app's
sources instead:

- `no_screen_ships_a_hover_only_affordance` — no `:hover`, `onmouseenter` or
  `onmouseover` anywhere in `crates/app/src`. A 10-foot shell has no pointer, so
  an action that exists only while the mouse rests on a control is unreachable.
- `no_screen_ships_motion` — no `animation`, `transition`, `backdrop-filter` or
  `scroll-behavior` with a live value (only `none`/`auto`, which is the written
  rule itself). Safe mode's "animations and blur off" (ADR-0007) therefore holds
  by construction; there is nothing to switch off.

## The probe (why there is no global stylesheet)

Two suspicions had to be separated: does a `<style>` element reach the window,
and do CSS custom properties resolve through inline styles? An Xvfb probe
answered both, by injecting `div{background:#ff00ff!important;}` and then
`background:var(--warning)` on the nav pills:

- the magenta rule **never painted** → the `<style>` element is ignored;
- the pills **did** turn amber → custom properties resolve fine.

That is why the tokens are variables (they work) while the hit floor is inline
(no selector available). `shell::motion_off_css` was removed rather than left as
a rule that never applied; the motion guarantee moved into the test above.

## A trap in the harness (worth remembering)

The first smoke runs measured the *old* UI: cargo was building into
`/work/target`, while the smoke scripts run `/work/target-arch/debug/pitagames`.
The stale binary made the token pass look broken — pills measured 29 px against a
48 px floor. **Build with `CARGO_TARGET_DIR=/work/target-arch`** (the container's
`CARGO_TARGET_DIR`) or the smoke script tests yesterday's binary. The probe that
settled it was `grep -c "var(--warning)"` on the binary the script actually ran.

## Verification

- **`crates/core`**: 97 → **105** tests (+8 `design`: contrast against
  independent worked examples, AA on every shipped pair, the floor under every
  accepted `ui_scale`, hit areas, the CSS variable names, hex round-trip).
- **`crates/app`**: 210 → **214** (+4 net in `shell`: the root carries every
  token in both shells, the console palette/tokens, the caption token on the
  header, the hit floor inline, plus the hover and motion guards; three
  superseded tests removed).
- `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets --
  -D warnings` are clean in `archlinux:latest`; the pure crates pass on macOS.
- **Xvfb runs in `archlinux:latest`** (script `target-arch/foot-smoke.sh`):
  - console @1080p — the nav pill measures **48 px** (y 137–184) and the hero
    title, section labels and footer hints all draw at the console scale;
  - console @4K — the same layout at the 4K root, still 1280×800 logical (the
    container has no window manager to grant fullscreen, and no HiDPI scale
    factor is exercised);
  - desktop @1080p — the pill measures **28 px**, the wordmark 28 px and the
    captions 12 px; `F11` toggles to the console chrome and back with the tokens
    following, never a stale inline size.

## Known limits

- The sweep covers the console-critical screens; **History, Account, Logs and
  Controls** still carry their own literals and are the next pass.
- **4K/HiDPI is not validated**: the container has no window manager (fullscreen
  is a request it ignores) and no scale factor, so the 4K run proves the layout
  survives the root size, not that WebKit's device pixel ratio is right. A real
  4K display on the RX 9070 is the check.
- **No TV.** Overscan, 10-foot readability and couch distance remain "not tested
  on a TV" (ADR-0004); the floor is a monitor proxy.
- The desktop shell is still decorated (frameless chrome needs custom
  close/minimize controls), and the monitor preference still applies on a toggle
  rather than at startup.
- The hit floor is repeated inline per control (no stylesheet), so a new pointer
  control must remember `shell::HIT_FLOOR`; the two guards cannot catch a control
  that *forgets* it, only one that ships motion or a hover-only affordance.
- `min-width:var(--hit-min)` changes a flex control's intrinsic width; this is
  intended, but it is the reason a stylesheet-only portability story is not
  available.
