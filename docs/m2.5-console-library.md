# M2.5 — the console library, its filters and the console game page

Status: implemented; `crates/app` builds, lints and tests in `archlinux:latest`
(**262** tests, `pitagames-input` at 98) and an **end-to-end Xvfb run** in the
same container at 1080p completed the exit criterion — entered console mode,
browsed the Library, filtered to one store, opened a game, launched it, quit it
and landed back in console mode. Nothing here has met a real controller or a TV
(ADR-0004).

This is the console-library slice, on top of the input layer
(`docs/m2.5-input.md`), the focus graph (`docs/m2.5-focus.md`), the gamepad pump
(`docs/m2.5-gamepad.md`), the shells (`docs/m2.5-shells.md`), the hints
(`docs/m2.5-hints.md`), the remap UI (`docs/m2.5-remap.md`), the console home
(`docs/m2.5-home.md`), the on-screen keyboard (`docs/m2.5-osk.md`), the launch
hand-off (`docs/m2.5-handoff.md`), the overlay (`docs/m2.5-overlay.md`) and the
10-foot design pass (`docs/m2.5-design.md`). Those built the couch shell and its
navigation model; this slice makes the **Library** and the **game page**
controller-first, so the couch path browse → open → launch is a pad alone.

## Why this slice exists

The console shell already opened on the couch Home, but its Library was still the
windowed desktop grid: a dense pointer-oriented layout with a text search field
and no way to narrow a large library from a pad. Opening a game showed the desktop
detail page. The plan's console table (plan §7, *Console mode*) asks for a
full-screen tile grid with **filter chips (store, installed, updates) and sort**
and a game page with a **controller cheat-sheet footer**; the M2.5 checklist
carries it as "console library grid + filters + game page". The acceptance bar is
**controller-only operation** — no pointer, no focus trap, every action reachable
— so this slice is that surface, and the desktop shell gets the same filter chips
so the two shells cannot drift.

It is hardware-independent (the same fixture Steam root the other smoke runs
used), so it ships while the M0 hardware closer waits on machine access.

## What ships

Five tickets, in order:

### The shared filter model replaces the navigation query

`crates/app/src/filter.rs` is a new framework-free module — the one place that
decides what the library shows and in what order:

- **`LibraryFilter { query, stores, installed_only, needs_attention, sort }`** —
  one value on `Navigation`, reached through the existing `use_session()` handle
  (ADR-0027 puts the library query in `Navigation`, so the filter replaces it
  there rather than becoming a separate app signal; no new ADR). `text_focused`
  stays on `Navigation`.
- **`Sort { Title, Playtime, Recent }`** with fixed directions (Title A–Z,
  Playtime most-first, Recent newest-first) — no separate direction field that
  could fall out of step with the Sort label.
- **`LibraryFilter::apply(&Library) -> Vec<usize>`** — pure; it returns **indices
  into `Library::games`**, so the windowed grid keeps one flat list. `narrows()`
  is true for a query, a store subset or either toggle (a `Sort` alone only
  reorders, so it never empties the grid); `clear()` restores the neutral filter.
- **`crates/app/src/navigation.rs`** lost `query` and gained
  `filter()`/`filter_mut()`/`clear_filter()`/`search(query)` — `search` sets the
  query *and* lands on `View::Library`, the one path the Library's box, the
  Library's on-screen keyboard and the Home's search all share.

### The chip row and the ragged focus graph

`filter.rs` also owns the row's model:

- **`Chip::{Installed, Updates, Store(Store), Sort}`** — each knows its `label`,
  whether it `is_active` and what a press `toggle`s. `chips(&Library)` builds the
  fixed order `[Installed] [Updates] <one chip per non-empty store> [Sort]`, so an
  empty store contributes no chip and the row never offers a filter that would
  empty the grid. Store chips multi-select; an empty set means every store.
- **`ChipRow`** wraps the chips into as many lines as fit (`chip_columns` over
  `CHIP_MIN_WIDTH`, an unmeasured width puts them all on one) and owns the focus
  ids: a chip's id is its index and a tile's is `chip_count + index`, so one
  `ScreenFocus` stores a flat id like a grid index.
- **`ragged_graph(chip_count, chip_columns, tile_count, tile_columns)`** — the
  chips on row 0 (wrapping) and the tiles from the row after the last chip row, so
  `Up` from the top tile reaches the chips and no chip is unreachable when the row
  overflows. **Both shells** now move through this graph (the desktop grid's old
  fixed `move_focus(action, count, columns)` is gone), so the two shells cannot
  drift.

### The console grid, Back/empty, and search from the Home

- **`grid::GridGeometry::for_shell(shell, width)`** gains a per-shell tile floor:
  `TILE_MIN_WIDTH_CONSOLE = 320 px` (and a taller `TILE_CHROME_CONSOLE = 176 px`
  so the console type floor fits) against the desktop's `220 px`, so at 1080p the
  console shows fewer, larger tiles from the same geometry model (worked example:
  5 columns console / 7 desktop at 1920 px). A console tile also names its store
  and its install/update state explicitly (`GameEntry::install_status`, which is
  "anything but a plain install"), where the desktop card keeps them in its meta
  line.
- **Back clears before it leaves**: `back_action(filter)` is `ClearFilters` when
  the filter narrows and `Leave` otherwise, so a second `Back` (nothing left to
  clear) leaves the console Library for the Home. `empty_message(filter)` is the
  filtered-empty state, naming the query and always teaching `Back`.
- **Search from the Home**: `Action::Search` opens the on-screen keyboard on the
  console Home too; committing it calls `Navigation::search`, so the matches are
  shown on the Library immediately.

### The console top bar and `Tab`

- `navigation::DESTINATIONS` is the eight top-level destinations in the desktop
  pill order (`Detail` is deliberately absent — it is a page, not a
  destination), `cycle_destination(view, forward)` walks the ring and wraps, and
  `Navigation::tab(forward)` applies it (clearing the selection, like `go`).
- The console header renders a **passive destination strip** in place of the
  desktop search field: every destination, the current one highlighted, not
  focusable and with no hover rule (`shell::destination_strip_style`). No text
  `<input>` is mounted in console mode.
- `TabNext`/`TabPrev` — dead actions since they were defined — get their first
  consumer: `App` intercepts them (`tab_action`) before any screen sees them, so
  `Tab`/`E` (pad `RB`) and `Q` (pad `LB`) cycle destinations from anywhere.

### The console game page and the hint subset

- **`crates/app/src/game_page.rs`** is the page's framework-free model:
  `badges(entry, anticheat, forced_tool)` returns **only true badges** — the store
  always; the install/update word (amber unless a plain install); an anti-cheat
  badge **only when `AntiCheat::is_protected`** (EAC/BattlEye, danger-red, loud);
  and a forced compat-tool badge only for a Steam row pinned to one — and
  `primary_action(entry)` is the one rule the page and the Continue hero share
  (Play, else Install when the row's store has an installer — Steam or one of the
  three CLI stores — else Open, so a `Local`/imported row never offers a button
  that could only error). `crates/app/src/anticheat.rs` exposes the
  effective `kind` the badge reads.
- `crates/app/src/detail.rs` renders the console branch: a full-bleed hero (art,
  a legibility gradient, the badges, the title, the meta line and the one primary
  action) with `Back` overlaid top-left, and the existing Profiles/Runtime/
  Diagnostics/Command/Recent-launches panels kept **below the fold** so nothing is
  stranded. The desktop branch is unchanged.
- **`crates/input/src/hint.rs`** gains a per-screen subset: `ScreenHint { action,
  name }`, `hints_for(map, &[ScreenHint])` and `GAME_PAGE_HINTS = [Confirm →
  "Play", Menu → "Overlay", Back → "Back"]`. The footer hint row on the console
  game page filters `HINT_ACTIONS` through it, so the page advertises only the
  actions it exposes and in its own words; a remap changes the glyph with no
  second table.

### The vocabulary the slice fixes

The overloaded chip word **verified** was split. The chip is now **Updates**
(update/attention, backed by `stores::status::updates`); **verified** stays the
compat-DB claim, and the store `verify` command stays the CLI's file-integrity
repair. The plan's **"console library grid"** is `View::Library` and its
**"console game page"** is `View::Detail` — no new routes (ADR-0022). Recorded in
`AGENTS.md` and in `docs/console-mode.md`.

  true badges, `primary_action` including the installable-store gate, and the

  (`for_shell` per-shell columns at 1080p and 4K, the worked column counts),
  `shell` (the shared pill/action styles) and `library`
  (`install_status`/`install_is_wired`) tests.
- `pitagames-input`: **98** tests, of which **5 `hint`** are new (`hints_for` per
  screen, a subset drops the actions it does not expose, a subset skips an
  unbound action, and a subset follows a remap). `crates/core` is unchanged.
- `cargo clippy -p pitagames -p pitagames-input --all-targets -- -D warnings` and
  `cargo fmt --all -- --check` are clean in `archlinux:latest`; the pure crates
  pass on macOS.
- **End-to-end Xvfb run in `archlinux:latest`** at 1080p, console shell, fixture
  Steam root (two installed Steam rows) plus a seeded installed **Epic** row whose
  executable is a fake 6-second script (`target-arch/console-e2e-smoke.sh`,
  screenshots `target-arch/console-e2e-*.png`). The keyboard drives the *same*
  `Action`s a pad would (arrows = d-pad, `Enter` = `A`, `Esc` = `B`, `Tab` = `RB`,
  `F` = `Y`); the pad half is covered by the pump's `ReplaySource` tests. The run:
  1. entered console mode on the couch **Home**;
  2. `Tab` reached the **Library** — the 10-foot grid with the chip row
     `[Installed] [Updates] [Steam] [Epic] [Sort: Title]`;
  3. `Down` entered the chip row and `Right` walked to the **Epic** chip;
  4. `Confirm` toggled it and the grid narrowed to the single Epic tile;
  5. `Down` reached the tile and `Confirm` opened the **game page** — the
     full-bleed hero with only `EPIC` + `INSTALLED` badges, the Play button and
     the panels below, footer `Enter Play · M Overlay · Esc Back`;
  6. `Down` `Down` `Confirm` **launched** it: the log read
     `stepping aside while gizmo-1 runs`, `--onlyvisible` found **0** windows
     (the hand-off hid the window) and the fake game wrote its `started` marker;
  7. the game ended (`ended` marker), the window **returned**
     (`Gizmo ended; asking for focus`), the shell was still **console**, the
     header strip and the detail page were back, and the play strip read
     `Gizmo exited 0 after 6s`;
  8. SQLite held `launch_history: epic · gizmo-1 · native · exit 0 · 6s · exited
     0 after 6s` and the row's `playtime_secs = 6`.
- The `Tab` cycling, the chip row in both shells and the console game page had
  their own per-ticket Xvfb runs (`target-arch/topbar-smoke.sh`,
  `chip-smoke.sh`, `console-library-smoke.sh`, `gamepage-smoke.sh`); this run is
  the one that walks the whole exit criterion end to end.

## Known limits

- **The pad half is not hardware-tested.** The container has no `/dev/input`, so
  every smoke run uses the keyboard (which drives the same `Action`s through the
  same focus graphs); `gilrs` button/axis conversion is covered only by
  `crates/input`'s tests and the pump's `ReplaySource`. No TV is attached to
  either machine, so 10-foot readability and overscan remain "not tested on a
  TV" (ADR-0004) — the checklist in `docs/console-mode.md` is the validation path.
- **The container has no window manager**, so the console shell is a 1280×800
  window inside the 1920×1080 root rather than truly fullscreen; the run proves
  the layout, not fullscreen.
- **The filter is in-memory only.** It survives a view switch and a shell toggle
  within a session and resets on restart; persistence is deliberately not a config
  surface.
- **History, Account, Logs and Controls keep their desktop layout** in console
  mode. They stay reachable (through `Tab`), but only the Library, Home and the
  game page got the 10-foot treatment; the design pass's literal sweep also stops
  at the console-critical screens.
- **A sort alone is not a filter to clear.** `Back` on a sorted-but-unnarrowed
  Library leaves the screen; that is intended (a sort hides nothing), but it means
  a couch player who only cycled Sort cannot undo it with `Back`.
- **The `Context` action has no consumer.** It is defined and bound (pad `West`)
  but no screen reacts to it yet.
- **Not driven against a real controller or a TV**, and not against a real store
  library — the seeded row is the shape a `stores sync` writes, not a live sync.
- **The detail page's props are still threaded.** `DetailProps` carries 18 fields
  because ADR-0027 defers the concern handles (`Play`, `Installs`, `Downloads`)
  to a later slice; this is the documented interim state, not the final shape. The
  session-handle slice replaces the threaded fields with the handles.
- **The smoke scripts and screenshots are untracked.** Ticket #7 said the run
  artifacts would be committed under `target-arch/`, but `target-arch/` is
  gitignored and no prior smoke script is tracked, so this slice keeps that
  convention: the scripts (`target-arch/console-e2e-smoke.sh`, `topbar-smoke.sh`,
  `chip-smoke.sh`, `console-library-smoke.sh`, `gamepage-smoke.sh`) and their
  screenshots exist on disk only. This is a deliberate deviation from the ticket
  wording, not a missing artifact.
