# M3.5 — the NR uninstall

Uninstalling DLSSNR has two ways back, and the launcher prefers the vendor's:

1. **Upstream's own `remove` route.** Upstream's `install.sh` writes every path
   it installs into `dlssnr-amd-install.txt` in the game directory, and
   `bash install.sh <game folder> remove` deletes exactly those. It is the
   vendor's answer and it knows files our manifest cannot, so it is the first
   choice.
2. **The launcher's manifest + `.gl-backup/` restore.** Upstream's `remove`
   only *deletes*: it never puts back a game file an install overwrote. Our
   `pitagames_mods::ModManifest` records that, so it is the fallback — and the
   only path that can promise the game folder came back byte-for-byte.

Plan §6 item 9; ADR-0024.

Ticket: #32 (part of umbrella #8).

## Pieces

| Crate | Responsibility |
|---|---|
| `platform::nr_uninstall` (`crates/platform/src/nr_uninstall.rs`) | the upstream `remove` argv, the strategy, and the manifest fallback with its BLAKE3 check |
| `app::nr_install` (`crates/app/src/nr_install.rs`) | `spawn_remove`: upstream's `remove` on the shared terminal |
| `app::nr_install_view` (`crates/app/src/nr_install_view.rs`) | the Graphics screen's **Uninstall DLSSNR** button |

```text
 strategy(package, game)
      │
      ├── UpstreamRemove ──► remove_plan ──► bash install.sh <game dir> remove
      │
      ├── Manifest       ──► restore_manifest
      │                        ├── verify (BLAKE3, per file + tree)
      │                        │     └── mismatch ──► report the changed files, do not proceed
      │                        └── ModManifest::restore ──► report the pre-install tree hash check
      │
      └── Nothing
```

## Choosing the path

`strategy(package_dir, game_dir)` is the one decision:

- `UpstreamRemove` when the package's `install.sh` **and** the game's
  `dlssnr-amd-install.txt` are both on disk — upstream can actually remove
  something;
- `Manifest` when a launcher manifest is installed but upstream cannot run;
- `Nothing` when neither is present.

`remove_plan(package_dir, game_dir)` composes the argv — never a shell string —
`bash <package>/install.sh <game dir> remove` with the game's executable
directory as cwd, refusing a package with no `install.sh` or a game directory
that is gone by name.

## Check before touching

`restore_manifest(root)` does **not** restore blindly. It first runs
`ModManifest::verify` — the BLAKE3 per-file and whole-tree check against what the
manifest recorded. When the installed tree no longer matches (a created file was
modified or deleted, a backup was tampered with, or an unrecorded file appeared),
the report carries the files that changed and the restore **does not run**,
because a restore over a tree that no longer matches the ledger cannot be
trusted. Only a clean match restores, and the report says whether the directory
reached the manifest's pre-install hash.

`UninstallReport::summary()` is the one line the panel shows, so a refusal, a
clean restore and a restored-but-not-byte-identical tree each read plainly.

## Verification

Pure crates (macOS host and CI):

```bash
cargo test -p pitagames-platform nr_uninstall
cargo clippy -p pitagames-platform -p pitagames --all-targets -- -D warnings
cargo fmt --all -- --check
```

`nr_uninstall` covers, over a `tempfile` tree: the `remove` argv with the exe
directory as cwd, a package with no `install.sh` and a missing game directory
refused by name; the strategy preferring upstream when its installer and ledger
are both present and falling back to the manifest otherwise; a clean install
uninstalled back to its exact pre-install hash (the deleted and restored files
named); a modified created file reported with the path and both hashes, with the
tree and the ledger left untouched; an unrecorded file reported as a whole-tree
mismatch carrying the manifest's post-install hash; and no-manifest as an error.

`app::nr_install` adds one test: a fixture `install.sh` whose `remove` route
deletes the `$1` ledger runs on the shared terminal and its own line streams
through.

The GUI is built, linted and tested in `archlinux:latest`
(`CARGO_TARGET_DIR=/target/<ticket>`).

## Known limitations

- **Not run against a real release or GPU.** The package is fetched by ticket
  #12, whose live HTTP `Fetcher` is still its open item, and no target machine
  has been reachable. The upstream argv is the shape upstream's release notes
  document (`bash install.sh " " remove`); the container smoke run would seed a
  fixture `install.sh`.
- **An NR install run from the panel does not yet write a launcher manifest.**
  It runs upstream's `install.sh` directly (#29), which leaves only upstream's
  own ledger, so the primary path is upstream's `remove`. The manifest fallback
  is the launcher-managed path (the same `ModManifest` Tier B uses) and is
  exercised from a fixture tree.
- **Upstream's `remove` is not byte-for-byte.** It deletes what it installed and
  does not put back a game file it overwrote; the launcher manifest is the only
  path that promises that.
- **The button is pointer/tab reachable but is not on the screen's gamepad focus
  graph yet**, like the install panel (#29).
- Not validated on the RX 9070 or the RX 5700 XT.
