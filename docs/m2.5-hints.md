# M2.5 — glyph hints and the auto-hidden cursor

Status: implemented and container-verified by tests; `crates/app` builds, tests
and lints in the Arch container. The pad has not met real hardware yet, and the
hint row and the cursor/timer seam have not been exercised in an Xvfb smoke run
(only the framework-free labels are unit-tested).

## What it is

The last device that produced input decides how the shell speaks to the
player. A pad press switches the hint row to the pad's glyphs and lets the
pointer hide; a key press or a mouse move switches back to the keyboard's
labels and shows the cursor. The hint row is the one place the shell says
"press this to do that", so a couch player never has to guess which button
opens a screen.

## The hint module (`crates/input/src/hint.rs`)

Framework-free and unit-tested. It owns the *labels*, not the drawing:

- `Hint { action, label }` — one row: the action and the compact glyph
  (`South` → `A`, `Key::Enter` → `Enter`, `Mode` → `Guide`).
- `HINT_ACTIONS` — the actions a footer names, in order: Confirm, Back,
  Search, Menu, Guide. A screen that hides one filters the row before it draws.
- `hints(&InputMap)` — reads the map's *first* binding per action and labels
  it. An action the map leaves unbound is skipped, so a row never claims a
  control a remap removed. A remap changes the hints with no second table to
  keep in sync.
- `binding_label`, `button_label`, `key_label`, `axis_label`, `stick_label` —
  the per-shape labels; `action_label` is the human name (`Confirm`, `Shell`).
- 6 tests: the gamepad row, the keyboard row, a stick binding, an axis binding,
  every action named, and an empty map producing no rows.

The labels are text, not icon assets: the shell has no SVG icon set yet, and a
label is readable in a screenshot. A future icon pass can replace the strings
without moving the row's geometry.

## The app seam (`crates/app/src/main.rs`)

- **One source of truth for "last device".** `pad_active: Signal<bool>` is set
  `true` by any pad press in the gamepad pump and `false` by any key press in
  the keyboard pump or any pointer move on the root element. The hint row and
  the cursor read the same signal, so they cannot disagree.
- **The hint row.** `input_maps` is a `Signal<InputMaps>` (the same maps the pad
  worker runs on, and the ones the remap UI writes). The row picks the last
  pad's map — the worker names every device by GUID — or, with no pad seen,
  `for_device("", true)`; for the keyboard it picks `keyboard()`. It renders each
  `Hint` as a glyph chip plus its action name in a footer at the bottom of the
  window. The row is rebuilt when `pad_active` changes and when a remap is saved,
  not on every pointer move.
- **The auto-hidden cursor.** A plain `Rc<Cell<Instant>>` records the last
  pointer move without re-rendering. One `tokio` future polls every 250 ms and
  hides the cursor when the pad is active and the pointer has been idle for
  2 s. A pointer move shows it again. The hidden state is appended to the root
  style as `cursor:none;`, so the base style is untouched and the property is
  named on both branches (the Dioxus style setter trap).
- **The hint row follows the remap.** The gamepad worker reports each device's
  SDL GUID (`GamepadEvent::Device`), so the pad branch reads *that* pad's stored
  map: a remap changes the hints with no second table and no restart
  (`docs/m2.5-remap.md` closed the "built-in layout only" limit).

## Known limits

- The hint row is global: every screen draws the same five actions. A screen
  that hides an action (the sign-in modal, the detail page) will want its own
  filtered row in the next slice.
- The cursor auto-hide runs in both shells; the desktop shell may want it only
  in the console shell.
- The row and the cursor auto-hide have not been seen in a smoke run yet; no
  pad or TV has met them.
- The labels are plain text; the icon pass is later.
